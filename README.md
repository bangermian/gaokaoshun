# 高考顺 gaokaoshun

> 把高考录取**位次**当作股票 **K 线**来分析：大盘、板块、个股三个维度，看一所学校、一个地区、一个层次的高校历年到底变难还是变容易。

位次（排名）不受试卷难度影响，跨年可比，所以它比分数更适合做趋势分析。
本项目用 ECharts 画出 K 线 + 成交量柱 + 分差柱，并聚合出区域指数与板块指数。

## 快速开始

数据只在你的浏览器里解析，不会上传到任何服务器。

### 方式一：本地一键启动（推荐，零依赖）

**把 Excel / CSV 放进 `data/` 目录，双击 `启动.cmd`，就完事了。**

页面启动时会自己向本地服务器要 `data/` 的文件清单并逐个加载，
之后每 45 秒检查一次——目录里新增或改动了文件，它会自动重新加载，不用再点任何按钮。
子文件夹名会被当作「院校所在地」。

它调用 `tools/serve.ps1`（纯 PowerShell 写的静态服务器，不需要 Node / Python），
自动打开 <http://127.0.0.1:8137/>。

> 为什么不能直接双击 `index.html`？本项目用 ES Module 组织代码，
> 浏览器禁止在 `file://` 下加载模块。直接打开时页面会显示明确提示，而不是白屏。

### 方式二：在线访问

部署在 GitHub Pages 后直接打开项目主页。静态托管没有文件清单接口，
所以这种方式需要点右上角「加载数据」手动选择目录——功能一样，只是不自动。

### 方式三：已有 Node.js

```bash
node tools/serve.mjs        # 默认 http://127.0.0.1:8137/
npm start
```

### 一张表就够了（推荐）

点顶部「**📄 模板**」下载 `高考顺_数据模板.xlsx`，在「分数数据」表里一行填一个专业：

| 年份 | 招生省份 | 院校名称 | 院校所在地 | 板块 | 专业名称 | 最高分 | 最低分 | 最高位次 | 最低位次 | 录取人数 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 2025 | 天津 | 天津工业大学 | 天津 | 双一流 | 计算机科学与技术 | 630 | 610 | 7000 | 11000 | 10 |
| 2024 | 天津 | 天津工业大学 | 天津 | 双一流 | 计算机科学与技术 | 620 | 600 | 8000 | 12000 | 10 |

必填只有四列：**年份 / 招生省份 / 院校名称 / 专业名称**，外加 **最低位次**。
其余列缺失时会自动兜底（最高位次 ← 最低位次，最高分 ← 最低分，区块 ← 双非，所在地 ← 文件夹名）。

### 考生数表（强烈建议）

位次要除以该省当年考生总数，才能跨省、跨年比较。可以放在同一个工作簿的第二个 sheet，也可以单独一个文件：

| 年份 | 省份 | 考生数 |
| --- | --- | --- |
| 2025 | 天津 | 74000 |
| 2024 | 天津 | 70800 |

缺少的年份按 7 万估算，界面会提示「估算」。

### 仍然兼容旧格式

```
年份 招生省份 院校名称 板块 考生数.xlsx
例：2025 天津 天津工业大学 doublefirst 74000.xlsx
```

支持 `.xlsx` / `.xls` / `.csv`；CSV 自动识别 UTF-8 与 GB18030（Excel 导出的中文 CSV 常是后者）；
表头不必在第一行，会向下扫描 15 行自动定位。

## 软科评分与专业热度

### 软科评分

每所学校的软科（ShanghaiRanking）主榜评分已经内置：`data/软科评分.csv` 是原始数据，
`tools/build-ruanke.mjs` 把它编译成 `assets/js/ruanke.js`（602 所学校 × 2023–2026 四年）。

个股页的行情条会显示「软科 231.9（第 133）」，鼠标悬停能看到年份。

> 为什么编译进 JS 而不是运行时读 CSV：网站是纯静态托管，多一个文件就多一次请求，
> 而且 CSV 会和分数表抢解析流程。几百条数据直接打包最省事。
>
> 刷新数据：`node tools/build-ruanke.mjs`（软科接口一次返回整榜，四个年份四次请求）

### 专业热度

把**录取位次**放进「全省同一年所有专业」的位次分布里比较：

```
分位 P = 该专业位次在分布中的位置   （0 = 最难，100 = 最易）
热度 H = 100 − P                    → 0–100，越高越热
```

再给两个衍生指标：

| 指标 | 含义 |
|---|---|
| **校内溢价** | 该专业热度 − 该校当年按招生人数加权的平均热度。正数 = 比本校平均更难进 |
| **近三年** | 最近 3 年里最早一年与最新一年的热度差。正数 = 越来越热 |

在个股页选一个具体专业就能看到，例如：

```
专业热度 61.7 · 校内溢价 +0 · 近三年 +18.53
```

口径说明（重要）：

- **只在同省同年内比较**，跨省不可比（各省考生规模差一个数量级）
- 与学校整体热度**不是一套口径**：学校热度用的是「录取位次 ÷ 考生数」，
  专业热度用的是「在全省专业位次中的分位」，两者不要混着看
- 位次缺失的专业不参与；同省同年样本少于 2 个时不出结果（不瞎猜）

代码在 `assets/js/heat.js`，纯函数、可单测：`buildRankDistribution` / `percentileOf` / `heatOfRank` / `majorHeat` / `rankMajorsByHeat`。
## 计算口径

```
专业平均位次 = (最高位次 + 最低位次) / 2
院校收盘位次 = Σ(专业平均位次 × 录取人数) / Σ(录取人数)      # 缺人数时等权
开盘位次     = 上一年收盘位次（首年 = 当年收盘）
上/下影线    = 当年所有专业里最好 / 最差的位次
百分位       = 院校收盘位次 / 该省当年考生数 × 100
热度指数     = 100 - Σ(各校百分位 × 招生人数) / Σ(招生人数)
```

**为什么先算百分位**：位次的绝对值跨省不可比 —— 天津第 10000 名和北京第 10000 名不是一回事，
两省考生规模也不同。旧版直接把原始位次加权平均再除以一个分母，量纲是错的。
现在先把每所学校换算成「在本省排前百分之几」，再按招生人数加权，不同省份的学校才能放进同一个指数。

**视觉约定**：个股纵轴翻转（第 1 名在最上方），指数纵轴正常；
两种模式都满足「向上 = 变难考」，红色统一表示「比上一年更难」。

### 三个附加指标

```
录取率估计 = 招生人数 ÷ 收盘位次 × 100        # 把扩招/缩招的影响从价格里除掉
相对强度   = 本校百分位 − 同省同板块平均百分位  # 单位 pp；负数=比同类更难
断档标记   = |同比变化 − 中位数| > max(3×1.4826×MAD, 20%)
```

- **录取率估计**：位次变化可能只是扩招造成的（招 10 人扩到 30 人，位次必然下滑，竞争却没变）。
  这个指标同时控制了供给和考生规模。
- **相对强度**：单看绝对走势分不清"它变难"还是"全省变难"。图上灰色虚线就是同类基准，
  顶部「相对同类」显示差值。
- **断档检测**：用 MAD 而不是均值±3σ——后者会被异常值本身拽走（掩蔽效应）。
  突然断档的年份会在图上打橙色「断档?」标记，提示你别拿它做趋势判断。

## 三张图

| 图 | 内容 | 说明 |
| --- | --- | --- |
| K 线 | 开盘 / 收盘 / 最高 / 最低位次 | 个股按位次，指数按热度；叠加同类基准虚线 |
| **成交量柱** | 当年招生总人数 | 红=扩招，绿=缩招，与 K 线联动缩放 |
| **分差柱** | 专业最低分的 P10–P90 | 浮动柱状图，比 max−min 更抗极值 |

两张柱状图是刻意保留的：量价配合（招生缩减但位次上升 = 疑似"饥饿营销"）和分差扩张，
是判断"真热门"还是"虚火"最直观的两个信号。

### 已知局限

- **文理分科省份**：位次是科类内排名，而「考生数」填的是全省总数，会系统性低估百分位约一半
  （天津、浙江这类综合改革省份不受影响）
- **专业改名断档**：以专业名为键，"计算机科学与技术(中外合作)"改成"计算机类"就会被当成两只股票
- **样本量小**：录取数据通常只有 5–7 年，任何趋势判断的统计功效都很低。这张图是用来**解释历史**的，
  不是用来**预测明年**的——所以本项目不提供任何"金叉/死叉"信号
- **开盘价是构造值**：`开盘 = 上一年收盘`，K 线实体本质是"两年收盘之差"，请不要按股票形态学解读

## 数据采集：三种方式

| 方式 | 速度 | 拿到什么 | 要不要浏览器 |
|---|---|---|---|
| **直连抓取** `抓取数据.cmd` | 约 1 秒/校·年 | 专业分数线、招生人数、院校线 | 不用 |
| 浏览器插件（批量） | 约 6 秒/校·年 | 同上（计划数最完整） | 要 |
| 手工表格 | — | 任意 | 不要 |

### 方式一：直连抓取（最快，推荐先试）

掌上高考的分数线接口 `api.zjzw.cn/web/api/` **不校验签名**，`page` 参数直接翻页，
所以不需要打开页面、不需要点分页器。实测单请求约 90ms，
浏览器方案是 6 秒/校·年——快一个数量级。

**不用装 Node**：双击仓库根目录的 **`抓取数据.cmd`**，按菜单选就行。

```
  高考顺 · 数据抓取助手
  [1] 抓分数线（快，不用浏览器）
  [2] 合并招生人数（需要插件先导出）
  [3] 说明
  [0] 退出
```

选 `[1]` 后依次输入省份、名次区间、年份，会先 dry-run 预览再确认。

命令行（PowerShell）也可以直接调用：

```powershell
.\tools\crawl.ps1 -Province 天津 -From 1 -To 200 -Years 2026,2025,2024 -DryRun
.\tools\crawl.ps1 -Province 天津 -From 1 -To 200 -Years 2026,2025,2024
```

如果你装了 Node.js，还有一个并发版（更快）：

```bash
node tools/crawl.mjs --province 天津 --from 1 --to 200 --years 2026,2025,2024
```

输出：

- `out/专业分数线_<省份>_<区间>.csv`：年份/招生省份/院校/所在地/板块/专业/最高分/最低分/最高位次/最低位次/录取人数
- `out/…_含人数.csv`：合并招生计划后的版本（见下）

特点：

- **按专业大类聚合**——专业名只取第一个「（」之前，同一大类的班型合并，人数相加、最低分取最低、最低位次取最大（最差），和插件口径一致
- **断点续跑**——进度存在 `.cache/`，中断后重跑自动跳过已完成的
- **增量落盘**——每完成一个「校×年」立刻追加，崩了也不丢
- **自适应限流**（`.mjs` 版）：被限流就拉长间隔，连续成功后自动恢复并发

#### 关于限速（说清楚，不藏着）

站点按 **IP** 限流，不是按账号——请求里根本不带 Cookie，登录也没用。
撞上去不是等几秒就好，而是几分钟到几十分钟整段变慢。

所以工具的策略是**主动不撞**：

- 每抓完一个「校×年」停 ` -DelayMs `（默认 150 毫秒）
- 连续 3 次被限流 → 整体暂停 30–300 秒再继续
- 中途失败的任务不会被标记完成，重跑会自动补
- 宁可慢一点，也别触发退避重试——实测撞上去反而更慢

想更快可以调小 ` -DelayMs `，但阈值摆在那儿，调小了只会更频繁地触发限流。

> 换 IP（代理/VPN）确实能绕过单 IP 限制，但那是规避站点的访问控制，
> 违反使用条款，也可能连累账号，本工具不做这个。
#### 后台运行：关掉浏览器的后台节流

Chrome / Edge 会把**后台标签页**降频（定时器最低 1 分钟一次），超过 5 分钟直接冻结。
采集器是靠轮询等数据到达的，一冻结就停摆。

**Edge 不会更好**：它同为 Chromium 内核，还额外有「睡眠标签页」（Sleeping Tabs），
比 Chrome 更主动地挂起后台页。

解决办法是用带参数的窗口启动。仓库里提供了 **`启动抓取窗口.cmd`**，它用独立配置
（`.chrome-auto`）启动 Chrome，并带上这几个开关：

| 参数 | 作用 |
|---|---|
| `--disable-background-timer-throttling` | 后台标签页的定时器不降频 |
| `--disable-backgrounding-occluded-windows` | 被遮挡的窗口不算后台 |
| `--disable-renderer-backgrounding` | 后台渲染进程不降优先级 |
| `--disable-features=IntensiveWakeUpThrottling,CalculateNativeWinOcclusion` | 关掉「5 分钟后冻结」 |

效果：窗口最小化或被别的窗口盖住，采集照常跑，你可以同时干别的。

注意：**同配置的窗口已经开着时，新启动会复用旧实例，参数不生效**——先关掉再启动。
#### 招生人数怎么进表

**人数以插件为准，分数用直连抓。** 两者合并后完全一致（已核对：北京大学 2022 共 20 个专业、合计 36 人，逐行零差异）。

为什么这样分工：

- 直连能拿到招生计划，但**按专业组取时被每页 10 条的上限卡住**，
  专业多的组会被截断，导致每个专业的计划数系统性偏小
  （实测北京大学 2022：工商管理类真实 5 人，直连只能看到 1 人）
- 插件的招生计划页是完整渲染的，抓到的人数是对的

所以 `crawl.ps1` **默认不填人数**（只抓分数），人数留空等合并：

1. 插件抓一遍「一键抓取」→ 导出总表
2. `抓取数据.cmd` → `[1]` 抓分数（快，几百所几分钟）
3. `抓取数据.cmd` → `[2]` 合并人数（选题库文件 + 插件导出文件）

合并结果与插件导出逐行一致；没匹配到的行保持空白，不会写 0。

> 想让直连自己填人数也可以加 `-WithPlan`，但那是**近似值**，专业组超过 10 条时会偏小，
> 只适合做快速预览。

<summary>技术细节：直连是怎么拿计划的</summary>

招生计划走的是另一个接口（`api-gaokao.zjzw.cn/apidata/web`），它的规矩是每页最多 10 条，
超过 10 条时第 2 页才需要签名。所以按**专业组**分别取——每组通常不到 10 条，
一页就够，于是全程免签名。

流程（`crawl.ps1` 自动完成）：

1. 每所学校先查一次 `dic/provincescore.json`，拿到「哪些年份有数据 + 有哪些专业组」
2. 该省没有的年份直接跳过，不发那些注定白跑的请求
3. 每个专业组拉一页计划数，按专业大类合并
4. 「录取人数」优先用站点公开的录取数，没有才用计划数补

实测天津前 5 所 × 2024/2023：**69 行里 59 行有人数**，
清华 2024 九个专业全有，浙大 2024 四个大类全有。

> 覆盖率约 85–90%：某个专业组超过 10 条时只能取到前 10 条，脚本会在结束时提示有几个。
> 这部分可以用插件补——插件导出的 CSV 里「录取人数」是完整的。

**插件补数的流程**（只在需要时）：

1. 用插件（方式二）抓「一键抓取」并**导出总表**
2. 双击 `抓取数据.cmd` → 选 `[2] 合并招生人数` → 选分数线文件、拖入插件导出文件

合并按 **年份 + 院校 + 专业大类** 匹配，专业名同样只取「（」之前，
所以「机器人工程（荣誉项目班）」和「机器人工程（荣誉项目班；校本部）」算同一个。

没匹配到的行**保持空白，不会写 0**——空白表示"不知道"，0 表示"真的招了 0 人"，两者不能混。

命令行：

```powershell
.\tools\merge-plan.ps1 -Base out\专业分数线_天津_1-200.csv -Plan out\插件导出.csv
```

### 方式二：浏览器插件（`tools/gaokao-exporter.user.js`）

#### 路径 A：掌上高考批量

导出「院校最低线」（每年一条，无偏）。

1. 打开院校的「历年分数」页，页面自己会发一条带 `signsafe` 的请求
2. 从性能时间线里把这条**已经签好名**的 URL 捞出来
3. 实测该签名**不覆盖 `year` 参数**，于是原样重放、只替换年份 → 一次拿到 6 年数据
4. 逐校循环，结果存 `localStorage`，最后拼成模板 CSV

省份通过 `localStorage.localprovinceid` 切换，绕开了那个点不动的自定义下拉。

#### 路径 B：任意网页表格抓取

不依赖接口，也不依赖选择器——**页面上能看到的表格就能抓**：

1. 点「扫描本页表格」，自动按"数字密度"排序
2. 自动把表头映射到 `年份/院校/专业/最低分/最低位次…`，可手动改
3. 支持 `670/1301` 这种「分数/位次」合并在一个单元格的写法，自动拆分
4. 表头含「分数 + 累计人数」时自动判定为**一分一段表**，走另一套导出

学校改版也不用改脚本，因为拿的是**已经渲染好的 DOM**。

### 分数 → 位次 自动换算

大学官网普遍只发分数、不发位次（实测清华那个页面「位次」出现 0 次、「分数」20 次）。所以：

```
一分一段表（年份/省份/分数/累计人数）  →  加载进高考顺  →  分数表里缺的位次自动补上
```

在高考顺里**先加载一分一段表，再加载分数数据**，缺位次的记录会用累计人数自动换算；
换算不了的（分数低于表尾或没有该年表）会被跳过并提示条数。控制台不会静默丢弃。

### 安装

有两种装法，**扩展版更省事**（不用商店、不用登录、不联网）。

#### 方式一：本地扩展（推荐）

1. 双击项目根目录的 **`安装扩展.cmd`**
2. 在打开的 `chrome://extensions` 里打开右上角「开发者模式」
3. 点「加载已解压的扩展程序」，选中 `tools\extension` 文件夹

刷新任意网页，右下角出现「高考顺 · 采集器」即成功。Chrome 重启后依然生效
（每次启动会提示"停用开发者模式扩展"，点忽略即可）。

> 为什么不能一键装：Chrome 137 起禁用了命令行 `--load-extension`，
> 商店之外的扩展只能由用户在扩展管理页手动加载。

#### 方式二：Tampermonkey

1. 浏览器装 [Tampermonkey](https://www.tampermonkey.net/)（需能访问扩展商店）
2. 扩展图标 → 添加新脚本 → 清空 → 粘贴 `tools/gaokao-exporter.user.js` 全文 → 保存
3. 打开任意 `https://www.gaokao.cn/school/<id>/special` 页面，右下角出现面板

两个版本跑的是同一份代码：扩展的 `collector.js` 由
`node tools/build-extension.mjs` 从用户脚本生成，改一处即可。

### 已知限制（不隐藏）

| 限制 | 说明 |
| --- | --- |
| **院校级只有最低线** | 掌上高考路径拿的是全校最低分/最低位次，没有分专业、没有最高位次和分差 |
| **没有招生人数** | `special_plan` 接口每次只返回 5 条、`size`/`page` 都被签名锁死，页面分页是 antd 组件、合成事件点不动；页面也没有合计字段。所以导出里「录取人数」是空的——**宁可空着也不瞎填** |
| **部分年份没有位次** | 2021–2022 很多省份官方不公布位次，这些年份会被跳过 |
| **未登录只有前 5 个专业** | 页面固定 `size=5`，且签名覆盖该参数改不了；前 5 个专业是偏样本，所以脚本**不采用**专业级数据 |
| **批次已固定** | 同一年可能同时有本科批/提前批，脚本统一取「普通类 + 本科批」 |
| **表格抓取靠 DOM** | 图片版/PDF 版分数线抓不到，只能抓 HTML 表格 |

### 板块是标签，不是单选

985/211 院校同时属于 `92` 和 `双一流`，新型研究型院校也属于双一流。
所以「板块」页选「双一流」时 92 院校会一起算进来——这是刻意的。
`92` 板块应当是 `双一流` 的子集，两个数字相等才说明分类有问题。

数据里每条只写一个板块值，程序会按下面的规则展开成标签：

```
92            → 92 + 双一流
doublefirst   → 双一流
newresearch   → 新型研究型 + 双一流
s11           → 中外合办
shuangfei     → 双非
```

## 相比旧版的改动

旧版是一个 1368 行的单文件 `gaokaoshun.html`。

| 类别 | 旧版 | 现在 |
| --- | --- | --- |
| 数据填入 | 一个文件只能装一所学校一年，元数据写在文件名里，改格式极易出错 | 一张汇总表装下所有数据；附模板下载 |
| 指数算法 | 原始位次跨省加权平均，量纲不可比 | 先换算成省内百分位再加权 |
| 考生数 | 只取第一个文件的值当全局分母 | 按「省份 × 年份」维护，可单独一张表 |
| 均线周期 | 读取不存在的输入框 | 四个真实输入框，且周期超过样本量时自动不画 |
| CSV | 只认 xlsx/xls，2025 浙江数据被静默丢弃 | 支持 CSV，自动识别 UTF-8 / GB18030 |
| 涨跌配色 | 红柱实际出现在「变容易」的年份 | 统一「红 = 更难」 |
| 基准对比 | 只有绝对走势，分不清是本校变难还是全省变难 | 叠加同省同板块基准线 + 相对强度（pp） |
| 供给影响 | 扩招缩招被当成难度变化 | 新增录取率估计，把供给从价格里除掉 |
| 异常值 | 断档年份污染均线，无提示 | MAD 稳健检测，图上标「断档?」 |
| 分差口径 | max−min，专业越多极差越大 | 改用 P10–P90，更抗极值 |
| 聚合性能 | 4 处 O(n²) 重复扫描 | 单次遍历建桶 |
| 持久化 | 无，刷新即丢 | IndexedDB 自动缓存 |
| 导出 | 「导出全部」只是弹窗 | 真导出，每校一个工作表 |
| 结构 | 单文件 1368 行 | 10 个 ES 模块 + 独立说明页 |
